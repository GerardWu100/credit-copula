credit-copula: reading the code

What this project computes, how the files fit together, and which settings actually change the answer. Written for someone opening the repository for the first time.

How to use this

Sections follow the order the code runs in. Every code snippet is copied straight from the file named above it. Every number in a grey Sample data box came from running the project on this machine in this session; nothing is estimated. Coloured boxes flag design choices and traps.

The process in plain English

Take one BBB-rated corporate bond. Over the next year it can stay BBB, move up, move down, or default, each with a published probability and a matching end-of-year price. Now hold two of those bonds and ask how bad a year can get. The project answers that question twice. Method A pretends each bond's loss is a smooth bell curve with the right average and the right spread. Method B keeps the eight discrete rating outcomes and links the two bonds with a Gaussian copula, which is a way of tying two random draws together without changing either one's own distribution. Both methods use the same dependence input, 0.5. They agree on the average loss and disagree badly in the tail, and a separate exact-integration module proves the tail numbers are right rather than a simulation artefact.

01What the project is for, and the folder layout

The research question is narrow and worth stating precisely: if you feed the same dependence number, 0.5, into two different credit portfolio models, do you get the same tail risk? The answer is no, and the project measures the gap.

The repository started life as one Jupyter notebook. It was converted into a package without rewriting the analysis: the notebook cells became numbered Python files under src/credit_copula/steps/, and a small runner executes them in order inside one shared set of variables. Alongside that sits a second, genuinely reusable module, model.py, which computes the two-bond answer exactly by numerical integration instead of by random sampling.

Trap

There are two implementations of the same experiment: src/credit_copula/steps/ and blog/generate_charts.py. They are deliberately independent, they use different random number generators, and they will not print identical figures. If you change the rating table you must change it in both places, plus in tests/test_model.py, which carries a third copy of the same eight numbers.

02Entry points — cli.py, run_pipeline.py, demo.ipynb

# src/credit_copula/cli.py
# Smoke runs keep full logic but use fewer paths for a quicker sanity check.
SMOKE_OVERRIDES = {"n_simulations": 50_000}

    """Run the project pipeline from the command line."""
    parser = argparse.ArgumentParser(description="Run the notebook-derived pipeline.")
    parser.add_argument("--smoke", action="store_true", ...)
    parser.add_argument("--print-keys", action="store_true", ...)

In plain words

There is one command. It either runs the full experiment or a cut-down version, and it can list the names of everything the experiment left behind.

What it does

Input: command-line flags --smoke and --print-keys. Output: printed tables, five PNG files under outputs/figures/, and a dictionary of every variable the steps created. Role: the only supported way to start the pipeline; the script and the notebook both funnel into it.

All three entry points are the same thing wearing different hats:

Trap

--smoke only shrinks n_simulations, which steps 03 and 04 read. Step 09, the portfolio-size sweep, has its own hard-coded SCALING_SIMULATIONS = 200_000 and ignores the override entirely. Since step 09 repeats that for eleven portfolio sizes up to 100 bonds, it dominates the runtime, which is why smoke mode saves nothing. Treat --smoke as "cheaper tail estimates", not "quick run".

03The shared namespace — config.py and pipeline.py

This is the one structural idea you must understand before anything else makes sense.

# src/credit_copula/pipeline.py
def run_pipeline(context_overrides: dict[str, Any] | None = None) -> dict[str, Any]:
    """Run each generated step script with a shared notebook-style context."""
    config = ProjectConfig()
    context = build_execution_context(
        config=config, context_overrides=context_overrides
    )

    # Filenames are prefixed 01_, 02_, ... so lexical sort is run order.
    for step_path in sorted(config.steps_dir.glob("*.py")):
        context["__file__"] = str(step_path)
        source = step_path.read_text()
        exec(compile(source, str(step_path), "exec"), context)

    return context
In plain words

It reads each numbered file as text and runs it, handing every file the same bag of variables. A name created in file 02 is still there in file 09, exactly like running notebook cells one after another.

What it does

Input: an optional dictionary of overrides. Output: the context dictionary after all nine files have run, holding roughly 120 names including the simulated loss arrays and the results tables. Role: the engine. Nothing else in the package executes the analysis.

build_execution_context seeds that bag before the first file runs. The keys are the contract between the runner and the step files:

The three output folders are created with mkdir(parents=True, exist_ok=True) before any step runs, so a fresh clone does not fail on a missing directory.

Why it is written this way

The conversion goal was notebook parity, not a redesign. Using exec with one shared dictionary reproduces notebook semantics exactly, so the split scripts can be diffed line by line against docs/reference/credit-copula.ipynb. The price is that the step files are not importable modules and cannot be unit tested individually.

Why the root path is found this way

Path(__file__).resolve().parents[2] walks up from src/credit_copula/config.py: parent 0 is credit_copula/, parent 1 is src/, parent 2 is the repository root. Every output path is derived from that, so the command works from any working directory.

Trap

Ordering comes from sorted(glob("*.py")), which is plain alphabetical order on the filename. It works only because the files are numbered 01_ to 09_ with a leading zero. Add a tenth step named 10_... and it will sort between 09_ and nothing at all — that is fine — but a step named step_ten.py would run before 01_. Also, any stray .py file dropped in that folder becomes part of the pipeline.

The ordering is not cosmetic. Ratings run best to worst, so after the cumulative sum, default sits in the upper tail of the latent normal variable. Some credit models use the opposite sign convention; flipping the sign of every latent draw gives the same answer.

Trap

np.cumsum(probabilities) ends at 1.0000000000000002, not 1.0, because of floating-point rounding. That happens to be lucky: the copula step looks up a uniform random number in this array, and no uniform can ever exceed 1, so the lookup can never run off the end. Had the rounding gone the other way and produced 0.9999999999999999, an extreme draw would return index 8 into an eight-element array and crash. See the edge-cases table.

05Step 03 — Method A, the matched Gaussian

# src/credit_copula/steps/03_method_a_multivariate_gaussian_approximation.py
n_simulations = OVERRIDES.get("n_simulations", 1_000_000)
correlation = 0.5

initial_portfolio_value = 2 * initial_bond_value

# Loss if the bond lands in each rating state (positive means economic loss).
single_bond_losses = initial_bond_value - values
mean_loss_single = float(np.dot(probabilities, single_bond_losses))
var_loss_single = float(
    np.dot(probabilities, (single_bond_losses - mean_loss_single) ** 2)
)
std_loss_single = np.sqrt(var_loss_single)

# Equicorrelated Gaussian shocks for the two-bond portfolio.
correlation_matrix_mvn = np.array([[1.0, correlation], [correlation, 1.0]])
L = np.linalg.cholesky(correlation_matrix_mvn)

z_independent = np.random.randn(n_simulations, 2)
z_correlated = z_independent @ L.T

# Method A: approximate each bond loss as Gaussian with matched mean and variance.
losses_mvn = mean_loss_single + std_loss_single * z_correlated
credit_losses_mvn = losses_mvn.sum(axis=1)
In plain words

Work out the average loss on one bond and how much it typically varies. Then throw away the eight discrete outcomes and pretend the loss is a smooth bell curve with that same average and that same variability. Draw two such losses at a time, correlated at 0.5, and add them.

What it does

Input: the rating table from step 02 and n_simulations. Output: losses_mvn, an array of shape (n_simulations, 2) in dollars, and credit_losses_mvn, its row sums. Role: the benchmark that Method B is measured against.

The formula

One-name loss in rating state $k$, its mean, and its variance:

$$\ell_k = V_0 - V_k, \qquad \mu = \sum_{k=1}^{K} p_k\,\ell_k, \qquad \sigma^2 = \sum_{k=1}^{K} p_k\,(\ell_k-\mu)^2$$

Method A then replaces the discrete loss by a normal variable with those two moments, for names $i = 1, 2$:

$$L_i = \mu + \sigma Z_i, \qquad (Z_1,Z_2) \sim N\!\left(\mathbf{0}, \begin{pmatrix}1 & \rho \\ \rho & 1\end{pmatrix}\right)$$

$V_0$ is the starting bond price in dollars ($107.55$); $V_k$ is the end-of-year price in state $k$; $p_k$ is the probability of state $k$; $K = 8$ is the number of rating states; $\mu$ is the expected one-name loss in dollars; $\sigma$ is its standard deviation in dollars; $Z_i$ is a standard normal draw for name $i$; $\rho = 0.5$ is the correlation between the two draws. "Matched" means only the first two moments are reproduced — the shape is not.

The formula — why the Cholesky step works

The Cholesky factor $L$ is the lower-triangular matrix satisfying $L L^{\top} = \Sigma$, where $\Sigma$ is the target correlation matrix. If $X$ is a row of independent standard normals then $Y = X L^{\top}$ has covariance

$$\operatorname{Cov}(Y) = L\,\operatorname{Cov}(X)\,L^{\top} = L I L^{\top} = \Sigma$$

$I$ is the identity matrix. For $\rho = 0.5$ this gives $Y_1 = X_1$ and $Y_2 = 0.5 X_1 + 0.866 X_2$, so the second name shares half of the first name's shock.

The weakness, stated honestly

A normal distribution is symmetric and has no floor. Method A therefore produces portfolio "losses" as low as −24.00 dollars in the full run, even though the best possible real outcome is both bonds upgrading to AAA, a gain of 3.64 dollars. The approximation is wrong on both ends; the project's point is that it is wrong by much more on the right end.

06Step 04 — Method B, the Gaussian copula

# src/credit_copula/steps/04_method_b_gaussian_copula_on_rating_thresholds.py
# Same latent correlation as Method A; reuse Cholesky factor L from the prior step.
z_independent = np.random.randn(n_simulations, 2)
z_correlated = z_independent @ L.T

# Gaussian copula: correlated normals -> uniforms -> discrete ratings via inverse CDF.
uniforms = norm.cdf(z_correlated)
rating_idx1_copula = np.searchsorted(cumulative_probs, uniforms[:, 0], side="right")
rating_idx2_copula = np.searchsorted(cumulative_probs, uniforms[:, 1], side="right")

bond1_values_copula = values[rating_idx1_copula]
bond2_values_copula = values[rating_idx2_copula]

losses_copula = np.column_stack((
    initial_bond_value - bond1_values_copula,
    initial_bond_value - bond2_values_copula,
))
credit_losses_copula = losses_copula.sum(axis=1)
In plain words

Draw the same kind of correlated pair of normal numbers, but instead of turning them into dollar losses directly, convert each one into a percentage between 0 and 100, and read off which rating band that percentage falls into. The bond then takes exactly one of its eight real prices. The correlation lives entirely in the hidden normal draws; each bond on its own still shows exactly the published rating probabilities.

What it does

Input: cumulative_probs and values from step 02, L from step 03, n_simulations. Output: rating_idx1_copula and rating_idx2_copula, integer arrays of shape (n_simulations,) holding 0 to 7; losses_copula, shape (n_simulations, 2), in dollars. Role: the model the project is arguing for.

The formula

Convert the cumulative rating probabilities into cut points on the latent normal scale:

$$c_k = \Phi^{-1}\!\left(\sum_{j=1}^{k} p_j\right), \qquad k = 1,\dots,K-1$$

The rating drawn for name $i$ is the first band whose cut point the uniform draw has not yet passed:

$$K_i = \min\{\,k : U_i \le F_k\,\}, \qquad U_i = \Phi(Z_i), \qquad F_k = \sum_{j=1}^{k} p_j$$

and the loss is $\ell_{K_i} = V_0 - V_{K_i}$.

$\Phi$ is the standard normal cumulative distribution function and $\Phi^{-1}$ its inverse; $U_i$ is a uniform draw on $(0,1)$ obtained by pushing the latent normal $Z_i$ through $\Phi$; $F_k$ is the cumulative probability of the first $k$ rating states; $c_k$ is the latent cut point; $K_i$ is the rating index chosen for name $i$. Because $\Phi$ is increasing, comparing $U_i$ against $F_k$ and comparing $Z_i$ against $c_k$ are the same test — the code does the first, model.py does the second.

Whole-sample fact from the one-million-path run: the two methods produce almost the same average loss (0.9251 versus 0.9284 dollars) but the 99.9 percent worst case is 16.95 dollars under Method A and 61.95 dollars under Method B, a gap of 265 percent.

Why the marginals survive

This is the whole appeal of a copula. Whatever correlation you put into the latent normals, $U_i = \Phi(Z_i)$ is still uniform on $(0,1)$ for each name separately, so each bond still lands in AAA exactly 0.02 percent of the time and defaults exactly 0.18 percent of the time. Correlation changes only which pairs occur together. The tests confirm this to within $2 \times 10^{-16}$.

Trap: 0.5 is not a 0.5 correlation between losses

The input correlation = 0.5 applies to the invisible normal variables, not to the dollar losses and not to defaults. Pushing a smooth variable through eight discrete steps destroys most of the linear dependence. Measured on the full run: Method A's loss correlation came out at 0.5015, Method B's at 0.2033. The exact value from integration is 0.2013969. The correlation between the two default indicators, which is what a regulator would ask for, is smaller still: 0.0658607.

Why side="right"

np.searchsorted(cum, u, side="right") returns the number of cut points that $u$ has already passed, which is exactly the zero-based rating index. With side="left" a draw landing exactly on a cut point would be assigned to the better rating instead of the worse one. That is a probability-zero event with continuous draws, so the two behave identically in practice; "right" is the convention that matches the closed-above intervals in the formula.

The weakness, stated honestly

Step 04 draws a brand new set of random numbers rather than reusing step 03's z_correlated. The two methods are therefore compared on different random paths, so part of every reported difference is simulation noise rather than model difference. With one million paths this is small next to the effect being measured, and section 10 removes the doubt entirely by computing Method B exactly. But reusing the same draws would have been a strictly better paired comparison.

In plain words

Step 05 builds the headline four-column comparison table. Step 06 builds a longer table of ten distribution statistics for each method, plus the difference and the percentage difference.

What it does

Input: the two loss arrays. Output: results_df (2 rows) and stats_summary (10 rows), both printed and both left in the shared namespace. Role: the numbers quoted in the article.

The formula — Value-at-Risk

Value-at-Risk at confidence level $\alpha$ is the loss that is exceeded only $1-\alpha$ of the time:

$$\mathrm{VaR}_\alpha(L) = \inf\{\,x : \Pr(L \le x) \ge \alpha\,\}$$

$L$ is the portfolio loss in dollars; $\alpha$ is the confidence level, here 0.95, 0.99, or 0.999. In the steps this is estimated by np.percentile, which interpolates between neighbouring sorted observations. In model.py it is computed exactly by weighted_quantile, which does not interpolate because the loss can only take 64 distinct values.

Every Method B number is a sum of two entries from single_bond_losses and can be checked by hand: $5.53 = 5.53 + 0.00$ (one bond to BB, one stays BBB); $14.98 = 5.53 + 9.45$ (one to BB, one to B); $61.95 = 56.42 + 5.53$ (one defaults, one falls to BB); $112.84 = 2 \times 56.42$ (both default); $-3.64 = 2 \times (-1.82)$ (both upgrade to AAA).

Why the rank correlation is subsampled

stats.spearmanr sorts its inputs, so it costs about $n \log n$ and allocates rank arrays. On a million paths that is wasteful for a diagnostic. The code draws 200,000 rows without replacement using a dedicated generator seeded at 20251025, so the diagnostic does not consume draws from the global stream and does not shift any downstream result.

Trap: read the "% Diff" column with care

It divides by Method A's value in absolute terms. Method A's skewness is 0.000488, which is simply Monte Carlo noise around a true value of zero, so the percentage difference of 2,027,890 percent is arithmetically correct and completely meaningless. The same applies to the excess kurtosis row. Use the raw difference column for those two.

Trap: 95 percent VaR points the wrong way

At the 95 percent level the copula is the less risky model (5.53 against 9.46 dollars), because most of its probability sits on the single outcome "nothing happened". Only past about the 98th percentile does the discrete model overtake. A study that stopped at 95 percent would draw exactly the opposite conclusion to this project's.

08Steps 07–08 — the figures

In plain words

09Step 09 — how risk grows with portfolio size

# src/credit_copula/steps/09_portfolio_size_scaling_analysis.py
SCALING_SIMULATIONS = 200_000
VAR_PERCENTILE = 99
BOND_COUNTS = [1, 2, 3, 5, 10, 15, 20, 30, 50, 75, 100]


def correlated_standard_normals(
    n_sims: int, n_bonds: int, correlation: float
) -> np.ndarray:
    """Draw (n_sims, n_bonds) standard normals with constant pairwise correlation."""
    corr_matrix = np.full((n_bonds, n_bonds), correlation)
    np.fill_diagonal(corr_matrix, 1.0)
    cholesky = np.linalg.cholesky(corr_matrix)
    z_independent = np.random.randn(n_sims, n_bonds)
    return z_independent @ cholesky.T


def portfolio_var_99_copula(n_bonds: int, n_sims: int, correlation: float) -> float:
    """99th percentile portfolio credit loss under the Gaussian copula ..."""
    z_correlated = correlated_standard_normals(n_sims, n_bonds, correlation)
    uniforms = norm.cdf(z_correlated)
    rating_indices = np.searchsorted(cumulative_probs, uniforms, side="right")
    bond_values = values[rating_indices]
    per_bond_losses = initial_bond_value - bond_values
    portfolio_losses = per_bond_losses.sum(axis=1)
    return float(np.percentile(portfolio_losses, VAR_PERCENTILE))
In plain words

Repeat the whole experiment for portfolios of 1, 2, 3, ... up to 100 identical BBB bonds, and see whether spreading money across more names actually reduces risk per bond. Under both models it does, but much less under the copula.

What it does

Input: the rating table, plus mean_loss_single and std_loss_single from step 03. Output: scaling_results, an 11-row DataFrame, and 006_var_vs_portfolio_size.png. Role: the "does diversification help?" section of the article.

The formula — equicorrelated portfolio variance

For $n$ identical names each with loss variance $\sigma^2$ and pairwise correlation $\rho$, the total portfolio variance is

$$\operatorname{Var}\!\left(\sum_{i=1}^{n} L_i\right) = \sum_{i=1}^{n}\operatorname{Var}(L_i) + \sum_{i \ne j}\operatorname{Cov}(L_i,L_j) = \sigma^2\big[\,n + \rho\,n(n-1)\,\big]$$

$n$ is the number of bonds; $L_i$ is name $i$'s loss in dollars; $\sigma^2$ is the shared one-name variance; $\rho$ is the pairwise correlation. There are $n(n-1)$ ordered off-diagonal pairs, each contributing $\rho\sigma^2$. Per bond the standard deviation is $\sigma\sqrt{n + \rho n(n-1)}\,/\,n$, which tends to $\sigma\sqrt{\rho}$ as $n$ grows: correlation puts a floor under diversification. With $\rho = 0.5$ and $\sigma = 2.99178$, that floor is $2.115$ dollars per bond.

Why the copula per-bond curve is not smooth

It falls from 9.45 to 6.84, jumps back up to 7.69 at ten bonds, then drifts down again. That is not a bug. The portfolio loss can only take values that are sums of the eight discrete state losses, so the 99th percentile has to land on one of those attainable rungs. As $n$ changes, which rung sits at the 99th percentile changes in jumps. The Method A curve is smooth because a normal distribution has no rungs.

Trap

np.random.seed(42) is called in the middle of this step, resetting the global generator that steps 03 and 04 already used. It makes the scaling results reproducible regardless of n_simulations, which is useful, but it means the pipeline has two seeds in two places and the second one silently overrides the first for anything that runs after it.

The weakness, stated honestly

correlated_standard_normals builds a full $n \times n$ matrix and factorises it for every portfolio size. At $n = 100$ that is a 100 by 100 Cholesky decomposition repeated for no reason, and the draw matrix is $200{,}000 \times 100$ doubles, about 160 megabytes. The equivalent one-factor form used in blog/generate_charts.py, $\sqrt{\rho}\,F + \sqrt{1-\rho}\,\varepsilon_i$, gives the identical distribution with no matrix at all. The step file keeps the matrix version only because that is what the original notebook did.

10The audit layer — model.py

This is the only part of the package written as reusable, tested, documented functions. It answers the two-bond question exactly, with no random numbers anywhere, so that the simulation results can be checked rather than trusted.

marginal_loss_moments — one bond's loss, mean, and spread

What it does

Input: the probability vector, the value vector, and the starting price. Output: the eight state losses, the mean loss, the standard deviation. Role: the foundation for everything else in the module, and the thing the first test hand-checks.

validate_rating_inputs — refuse bad tables early

What it does

Input: probabilities and values. Output: nothing, or a ValueError. Role: checks both arrays are one-dimensional and the same length, that every probability is finite and strictly positive, that the probabilities sum to one within $10^{-12}$, and that the values are finite. Why it matters: a probability vector that does not sum to one would silently produce cut points that do not partition the real line, and every downstream number would be quietly wrong instead of loudly broken.

latent_rating_edges — probabilities to cut points

def latent_rating_edges(probabilities: NDArray[np.float64]) -> NDArray[np.float64]:
    placeholder_values = np.zeros_like(probabilities)
    validate_rating_inputs(probabilities, placeholder_values)
    interior_edges = norm.ppf(np.cumsum(probabilities)[:-1])
    return np.concatenate(([-np.inf], interior_edges, [np.inf]))
What it does

Input: eight probabilities. Output: nine edges, from $-\infty$ to $+\infty$. Role: turns the rating table into intervals on the latent normal scale, which is what the integration needs.

bivariate_state_probabilities — the 8 by 8 joint table, exactly

def integrand(first_latent: float) -> float:
    """Return the joint density integrated over name 2's interval."""
    upper_z = (second_upper - latent_correlation * first_latent) / conditional_scale
    lower_z = (second_lower - latent_correlation * first_latent) / conditional_scale
    conditional_probability = norm.cdf(upper_z) - norm.cdf(lower_z)
    return float(norm.pdf(first_latent) * conditional_probability)

joint[first_state, second_state] = quad(
    integrand, first_lower, first_upper,
    epsabs=QUADRATURE_ABSOLUTE_TOLERANCE,   # 1e-13
    epsrel=QUADRATURE_RELATIVE_TOLERANCE,   # 1e-11
    limit=QUADRATURE_LIMIT,                 # 200
)[0]
In plain words

For each of the 64 possible rating pairs, work out its probability by integration rather than by counting simulated draws. Sweep the first bond's hidden variable across its rating band; at each point, the second bond's hidden variable is normal around a known centre, so its band probability is a subtraction of two lookups.

The formula

For name 1's interval $(a_i, b_i]$ and name 2's interval $(a_j, b_j]$:

$$\Pr\!\left(a_i \lt Z_1 \le b_i,\; a_j \lt Z_2 \le b_j\right) = \int_{a_i}^{b_i} \phi(z) \left[\Phi\!\left(\frac{b_j-\rho z}{\sqrt{1-\rho^2}}\right) -\Phi\!\left(\frac{a_j-\rho z}{\sqrt{1-\rho^2}}\right)\right] dz$$

$Z_1, Z_2$ are the two latent standard normal variables; $a_i, b_i$ are the lower and upper cut points of name 1's rating band $i$; $\rho$ is the latent correlation; $\phi$ is the standard normal density and $\Phi$ its cumulative distribution function. The bracket is the standard result that conditional on $Z_1 = z$, the second variable is normal with mean $\rho z$ and variance $1-\rho^2$. Turning a two-dimensional integral into a one-dimensional one is what makes this fast and accurate.

Sanity check at zero correlation: joint[7, 7] becomes $3.24 \times 10^{-6}$, which is exactly $0.0018^2$. At correlation 0.5 the joint default probability is 37.5 times larger than independence would give.

Why integrate at all

Both bonds defaulting has probability 0.000122. To estimate that to within ten percent by simulation you need roughly a million paths, and the resulting loss correlation still wobbles: the project's own convergence table shows 0.15998 at ten thousand paths, 0.20019 at a hundred thousand, and 0.20439 at a million, against the exact 0.20140. Rare joint events are precisely where simulation is weakest and where credit risk lives.

weighted_quantile — VaR on a distribution with only 64 outcomes

What it does

Input: 64 loss values, their 64 probabilities, and a confidence level. Output: one dollar figure. Role: gives the exact tail numbers. It sorts the outcomes, merges duplicates with np.unique and np.bincount (several rating pairs give the same dollar loss), accumulates the probabilities, and returns the first value whose running total reaches the level. Why it matters: unlike np.percentile it never interpolates, so it can only return a loss the portfolio can actually suffer.

exact_two_name_metrics — the full benchmark

The formula — loss and default correlation

Because the two names are identical, both correlations simplify. Writing $\mu$ and $\sigma$ for the one-name loss mean and standard deviation:

$$\operatorname{Corr}(L_1,L_2) = \frac{\mathbb{E}[L_1 L_2] - \mu^2}{\sigma^2}, \qquad \mathbb{E}[L_1 L_2] = \sum_{i=1}^{K}\sum_{j=1}^{K} J_{ij}\,\ell_i\,\ell_j$$

For the two default indicators $D_i$, which are 1 if name $i$ defaults and 0 otherwise:

$$\operatorname{Corr}(D_1,D_2) = \frac{\Pr(D_1=1,\,D_2=1) - p_D^{2}}{p_D\,(1-p_D)}$$

$J_{ij}$ is the joint probability of name 1 in state $i$ and name 2 in state $j$; $\ell_i$ is the dollar loss in state $i$; $p_D$ is the one-name default probability, here 0.0018. The denominator is the variance of a Bernoulli variable, $p_D(1-p_D)$, which is the same for both names.

12The frozen evidence — blog/generate_charts.py

In plain words

A second, standalone version of the same experiment whose job is to write every published number into CSV files, so a reader can check the article without rerunning a million simulations.

What it does

Input: its own copies of the constants at the top of the file; it imports only exact_two_name_metrics from the package. Output: five CSV files under blog/data/ and two PNG files under blog/images/. Role: the reproducibility record for the bilingual article. Run it with MPLBACKEND=Agg uv run python blog/generate_charts.py.

Three things it does better than the step scripts

One. It uses np.random.default_rng(seed), a local generator, instead of the global np.random.seed, so nothing it does can disturb anything else.
Two. It computes Method A's portfolio VaR from the closed form, $n\mu + z_\alpha \sigma \sqrt{n + \rho n(n-1)}$ where $z_\alpha = \Phi^{-1}(\alpha)$, instead of simulating it. A Gaussian portfolio has an exact quantile, so simulating it only adds noise.
Three. It generates the latent variables in the one-factor form $\sqrt{\rho}\,F + \sqrt{1-\rho}\,\varepsilon_i$, where $F$ is a single common normal shock shared by all names and $\varepsilon_i$ is name $i$'s own independent shock. That reproduces constant pairwise correlation $\rho$ with no matrix factorisation, and it is processed in chunks of 20,000 rows to bound memory.

The comparable risk is reusing information across methods, and the code avoids that by drawing fresh random numbers for Method B.
"Why does the copula show a lower 95 percent VaR but a much higher 99.9 percent VaR?"Because 77.4 percent of the time both bonds simply stay BBB and lose nothing. That mass has to go somewhere, and it goes into rare large jumps. The Gaussian approximation spreads the same variance evenly and so has neither the calm centre nor the violent tail.
"Where does 0.5 actually enter?"Two places, identically: the correlation matrix in step 03, and the same Cholesky factor L reused in step 04. It applies to the hidden normal variables only.
"Why is the reported loss correlation 0.20 and not 0.5?"Thresholding is a non-linear transformation, and non-linear transformations destroy linear correlation. The exact figure is 0.2013969; the default-indicator correlation is smaller again at 0.0658607.
"How long does the full run take?"18.5 seconds on this machine with MPLBACKEND=Agg. --smoke took 22.3 seconds — no faster, because step 09 ignores the override.
"Why 61.95 dollars and not some rounder number?"It is $56.42 + 5.53$: one bond defaults and the other falls to BB. Portfolio losses can only be sums of two entries from single_bond_losses.
"Can I trust the simulated tail, or is it noise?"You do not have to trust it. model.py computes the same quantiles by integration with no random numbers, and gets 14.98 and 61.95 — identical.
"What breaks if I change the rating table?"Three files must change together: steps/02_data_setup.py, blog/generate_charts.py, and tests/test_model.py. Five test assertions carry hard-coded expected values and will fail loudly, which is the safety net.
"Why keep the notebook and the step scripts?"docs/reference/credit-copula.ipynb is the untouched original, kept so the split can be audited line by line. It is documentation, not code that runs.
"Which parts would you reuse in another project?"Only model.py. It is validated, documented, tested, and has no dependency on the pipeline. The step scripts are a preserved artefact.

20Limitations, stated honestly

  • The rating table is not sourced. The eight probabilities and eight prices are literals with no citation in the repository. They match the shape of a standard published one-year BBB transition row, but nothing in the code says which table, which year, or which agency.
  • The exact benchmark covers two names only. bivariate_state_probabilities is a double loop over rating pairs. There is no exact answer for the 100-bond portfolio; that curve is simulated and carries sampling error, visible as the non-monotone per-bond figures.
  • Correlation is a single number. One constant pairwise correlation of 0.5 across all names, all ratings, and the whole year. Real credit correlation varies by sector, by rating, and rises in stress.
  • The Gaussian copula has no tail dependence. That is a known property of the model, not of this implementation: as you go further into the joint tail, a Gaussian copula's dependence fades towards independence. The project shows the Gaussian copula is far more dangerous than a matched normal, but a Student-t copula would be more dangerous again, and that comparison is absent.
  • No recovery uncertainty. Default is worth exactly 51.13 dollars every time. In practice recovery is itself random and tends to be worse in the same years when defaults cluster, which would widen the tail further.
  • No spread or interest-rate risk. The eight end-of-year prices are fixed, so this measures migration and default risk only.
  • The nine step scripts are untested. Everything under steps/ is verified only by the fact that it runs and prints plausible numbers.
  • The experiment exists twice. The step scripts and blog/generate_charts.py implement the same study with different random number generators and separate copies of the constants. They agree today; nothing enforces that they keep agreeing.
